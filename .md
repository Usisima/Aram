# Prompt de desarrollo

## Proyecto

Desarrollar una plataforma web para un blog de matemáticas orientado a demostraciones matemáticas escritas en LaTeX.

La aplicación debe separar completamente el modo de lectura del modo de edición.

---

# Arquitectura general

Cada página del sitio será generada a partir de un prompt independiente.

La página principal aún no tiene especificación y se implementará posteriormente.

Las páginas actuales son:

* Materias
* Libros
* Demostraciones
* Editor integrado

---

# Vista pública

La vista pública será únicamente de lectura.

Los usuarios podrán:

* navegar entre materias
* navegar entre libros
* abrir demostraciones
* visualizar fórmulas matemáticas renderizadas
* realizar búsquedas
* cambiar entre modo claro y oscuro

No podrán modificar ningún contenido.

Toda la matemática deberá renderizarse usando LaTeX mediante KaTeX o MathJax.

---

# Vista privada (Administrador)

Existirá un modo administrador protegido mediante autenticación.

Solo el administrador podrá:

* crear materias
* crear libros
* crear demostraciones
* editar demostraciones
* eliminar contenido
* recompilar documentos LaTeX

Ningún usuario público podrá acceder al editor.

---

# Editor tipo Overleaf

Crear un editor inspirado en Overleaf.

La interfaz tendrá dos paneles.

## Panel izquierdo

Editor de código LaTeX con:

* resaltado de sintaxis
* numeración de líneas
* autocompletado
* búsqueda
* reemplazo
* plegado de código
* atajos de teclado
* guardado automático

Se recomienda Monaco Editor.

---

## Panel derecho

Vista previa renderizada.

Al presionar Compilar:

* se procesa el documento
* se renderiza nuevamente
* la vista previa se actualiza automáticamente
* si el documento pertenece a una demostración publicada, la página pública también refleja inmediatamente la nueva versión

La recarga debe ser dinámica, sin refrescar toda la aplicación.

## Página Materias

Mostrar una cuadrícula de tarjetas.

Cada tarjeta representa una materia.

Ejemplos:

* Álgebra
* Cálculo
* Topología
* Geometría Diferencial
* Probabilidad
* Análisis Real
* Análisis Complejo
* Lógica
* Teoría de Números

Cada tarjeta debe parecer la portada de un libro.

Características:

* bordes redondeados
* sombras suaves
* ilustración
* nombre de la materia
* color representativo
* animación al pasar el cursor

Al hacer clic se abre la materia.

---

# Página Libros

Dentro de una materia aparecen todos los libros utilizados.

Cada libro también se muestra como una portada.

Cada portada contiene:

* imagen
* autor
* título
* edición
* año
* descripción breve

Diseño tipo biblioteca digital.

Ejemplo:

Materia

↓

Cálculo

↓

Libros

* Apostol
* Spivak
* Rudin
* Stewart

Cada portada abre su contenido.

---

# Página Demostraciones

Dentro de cada libro aparecen las demostraciones.

Cada demostración será una Pill.

Diseño:

* bordes completamente redondeados
* sombra ligera
* animación suave
* efecto hover

Cada Pill muestra:

* título
* tema
* etiquetas

Ejemplo:

Demostración del Teorema Fundamental del Cálculo

Tema:
Integración


---

Al abrir una Pill aparece la demostración completa.

Debe soportar:

* ecuaciones
* matrices
* diagramas
* teoremas
* definiciones
* lemas
* corolarios
* referencias
* bibliografía

Todo renderizado con LaTeX.

# Objetivo visual

La plataforma debe transmitir la sensación de una biblioteca matemática moderna.

La navegación debe recordar una estantería de libros.

Cada libro debe sentirse como un volumen físico.

Cada demostración debe abrirse como una ficha elegante y minimalista.

El editor debe ofrecer una experiencia similar a Overleaf, con edición de LaTeX en tiempo real y vista previa sincronizada, manteniendo completamente separado el acceso de lectura pública y la edición privada del administrador.

# Prompt – Página de Materias

## Objetivo

Diseñar la página **Materias** como una biblioteca digital, inspirada en aplicaciones de cuadernos como Noteshelf o GoodNotes.

La sensación debe ser la de una estantería donde cada materia es un cuaderno o libro físico.

No debe parecer una lista tradicional ni un dashboard.

---

---

### Área principal

El resto de la pantalla muestra una cuadrícula de portadas.

Cada portada representa una materia.

Debe existir bastante espacio entre tarjetas.

La cuadrícula debe adaptarse automáticamente al tamaño de pantalla.


---

# Tarjetas de materias

Cada materia se muestra como un libro físico.

No utilizar tarjetas planas.

La portada debe tener:

* esquinas redondeadas
* lomo lateral
* ligera sombra
* textura de papel
* portada ilustrada
* efecto tridimensional muy sutil

Cada libro puede tener un color distinto.

Ejemplos:

Álgebra

→ azul oscuro

Análisis Real

→ verde

Topología

→ morado

Cálculo

→ naranja

Probabilidad

→ amarillo

Geometría

→ rojo vino

---

Cada portada incluye:

Nombre de la materia

Número de libros

Número de demostraciones

Última actualización

---

Al pasar el cursor:

* aumenta ligeramente de tamaño
* aumenta la sombra
* efecto de levantar el libro

---

Al hacer clic:

Animación de apertura.

Luego se entra a la página de libros de esa materia.

---

# Diseño de la portada

Cada portada debe parecer un libro real.

Elementos:

* textura elegante
* patrón matemático muy tenue
* etiqueta central con el nombre
* lomo ligeramente más oscuro
* sombras suaves

Ejemplo visual:

```
┌─────────────────────┐
│████                 │
│                     │
│      ÁLGEBRA        │
│                     │
│  12 libros          │
│  243 demostraciones │
│                     │
└─────────────────────┘
```

# Estilo general

Minimalista, limpio, elegante y académico.

Colores suaves.

Sombras discretas.

Bordes redondeados.

Transiciones fluidas.

El usuario debe sentir que está explorando una biblioteca física de libros de matemáticas, donde cada materia es un cuaderno elegante que da acceso a los libros utilizados en esa disciplina. La interfaz debe inspirarse claramente en aplicaciones de gestión de cuadernos, pero con una identidad visual orientada al ámbito matemático y académico.
